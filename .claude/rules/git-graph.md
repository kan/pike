# ブランチグラフとコミットタブの実装ルール

Git パネルの List / Graph 表示と、グラフの行から開くコミットタブ。git の呼び出し側と
Git パネルのほかの部分は `git.md`。

- ブランチマージグラフ: `git log` + `%P`（親ハッシュ）/`%D`（refs）で取得、`gitGraph.ts` のレーン割当アルゴリズムで SVG 描画。List / Graph 切替。取得範囲は下の「グラフを必要以上に深くしない」
- **レーンの列は幅に上限を持つ（#371）**。SVG に viewBox を付けず幅を `--graph-width` にして、はみ出したレーンをビューポートで切る（viewBox を付けると切れずに縮む）。上限が無いと、深いグラフでメッセージが右へ押し出されて見えなくなる。境目のドラッグで上限を変え（SourceTree と同じ）、`pike:git-graph-width`（マシンローカル・全プロジェクト共通）に残す。**保存するのは上限で固定幅ではない**: 浅いグラフは必要なぶんしか取らない。右端まで広げたら「全部出す」として記録し、あとで深くなったグラフも切らない
- **並びは `--date-order`（#374）**。SourceTree の既定の「日付順」と同じで、見比べたときに並びが食い違わない。`--topo-order`（ブランチごとにまとめる）は採らない: 並行するブランチが交互に並ぶぶんレーンは増えるが、並びが揃うことを優先する（幅は上の上限で抑えられる）。素の時刻順（オプション無し）にもしないこと: 時計がずれると親が子より先に出て、そのレーンが一覧の最後まで閉じない
- **自分のレーンの線は、実際に続いている半分だけ描く（#374）**（`GraphRow.hasChild` / `continuesDown`）。上半分は上の子がこのコミットを待っていたとき、下半分は第 1 親がこのレーンを引き継ぐときだけ。無条件に行の上端から下端まで描くと、分岐点（第 1 親が既に別のレーンにいる）とブランチの先端で行の境目に宙に浮いた線が出て、グラフが途中で途切れて見える
- **履歴は `LOG_PAGE`=200 件ずつ読む（#374、`stores/git.ts`）**。パネルの末尾の印（IntersectionObserver）が見えたら足す。足すときも `--skip` で続きだけを取らず、件数を増やして先頭から取り直す（ポーリングの取り直しと同じ経路に乗り、途中にコミットが増えても重複や抜けが出ない）。root か一覧 / グラフが変わったら 1 ページ目に戻す
- **グラフ表示の行のクリックはコミットタブ（`tabs/CommitTab.vue`）を開く（#374）**。一覧表示の行はファイルの一覧を開閉するが、グラフの行は高さがレーンの線の前提（`ROW_HEIGHT`）なので、その下に展開する場所を持たない。差分は `git_commit_patch`（第 1 親との `git diff -M`。親はパネルの `git log` が持っているので渡す。最初のコミットは `diff-tree --root`）で、ファイルごとに分けるのは `lib/commitPatch.ts`
  - **分割と右の差分は `components/PatchSplit.vue`**（作業中の変更のタブ #526 と共有）。
    左上と左下は slot で、一覧の行は `PatchFileRow.vue`、差分の表は `PatchLines.vue`。以下の
    分割・上下表示・折り返しの規則は 2 つのタブに同じく効く
    - **差分の表は子のコンポーネントに置いたままにする**（`PatchLines.vue`）。slot の中身は
      `PatchSplit` の render の中で描かれるので、表が同じ render にあると、コミットメッセージの
      打鍵や 10 秒ごとの `git status` のたびに、仮想化していない表の vnode が行数ぶん作り直される
  - **コミットタブの配置は SourceTree の下半分にそろえる（#396）**: 左上にメタと
    メッセージ、左下に変更されたファイルの一覧、右に選んだ 1 ファイルの差分。分割線は
    ドラッグで動く（`useDragResize`。縦に動かすほうは `axis: 'y'`）。全ファイルの差分を縦に
    積むと、目当てのファイルまでスクロールし続けることになり、大きいファイルを畳む仕掛けも
    別に要る。**1 ファイルずつ描けばその仕掛けが丸ごと要らない**
    - **分割の位置は比で持ち、開き方と一緒に `pike:commit-split` に覚える**（マシンごと・
      全プロジェクト共通。グラフの列幅と同じ扱いで、同期の対象にはしない）。px ではなく
      比なのは、覚えた値をウィンドウの大きさが違う環境でも使うため。**下限だけは px で
      見る**: 比の下限にすると、狭いウィンドウで左の列が読めない幅まで詰められる
    - **右のペインは統合形式と「新旧を上下」を切り替えられる**（#396）。**上下の行は
      統合形式の行を濾して作る**ので、差分を取り直さない（新しい側は削除行を、古い側は
      追加行を落とす）。**hunk の見出しは両方に残すこと**: 飛ばした範囲の目印なので、
      片方から落とすと離れた変更どうしが続きの行に見える
      - 左右に並べる表示は持たない。1 ファイルの文字単位の強調が要るときは、Git パネルから diff タブを開く
    - **空白の違いを無視できる**（#453。`git_commit_patch` の `ignore_space`、diff タブの側は
      `git-diff.md`）。**ファイルの一覧は元の差分から作り、右の行だけを差し替える**
      （`spaceFiles`）: `-w` を付けると、空白だけが違うファイルは出力から丸ごと消える（ヘッダも
      出ない）ので、一覧をそちらから作ると、切り替えた瞬間にファイルが消えて選択も見失う。
      取り寄せるのは初めて切り替えたときで、**取れてから見方を変える**（先に変えると、
      取れるまで全ファイルが「空白以外の変更はありません」に見える）
    - **ドラッグ中は Vue を通さない**（diff タブの `--split` と同じ。理由は `git-diff.md` の
      「スクロールとドラッグの最中は Vue を通さない」）。右のペインは仮想化していない表なので、
      `:style` に載せると mousemove ごとに行数ぶんの vnode が作り直される
    - **ブラウザのタブは、Git パネルが開いているあいだ隠れる**（#396。理由は
      `frontend.md` の「手前に浮くものの数」）
  - **メッセージの 1 行目に見出しの様式を当てない（#396）**。件名と本文は 1 つの文章で、
    git 自身も 1 行目を特別な書式として扱わない。太く大きくすると、本文の 1 行目だけが
    見出しに見える
- **作業中の変更のタブ（`tabs/ChangesTab.vue`、#526）**: まだコミットしていない変更をコミットタブと
  同じ配置で見る。左上はコミットメッセージの欄、左下はコンフリクト / ステージ済み / 未ステージの
  一覧、右は選んだ 1 ファイルの差分。入口は Git パネルの 2 か所（グラフの先頭の「コミットされて
  いない変更」の行と、ステージ済み・変更の見出しのボタン）。**プロジェクトごとに 1 枚**
  （`addChangesTab`）で、セッションには残さない
  - **一覧は `gitStore.status` から作り、差分の行だけをタブが取る**（`git_working_patch` で
    `git diff --cached -M` と `git diff -M` を並べて取り、パスで引く）。一覧を差分から作らないので、
    `-w` で空白だけのファイルが差分から消えても一覧は変わらない（コミットタブの `spaceFiles` が
    要らない）。差分に居ないファイルは代わりの空のファイルを出す（名前やモードだけの変更）
  - **未追跡のファイルは選んだときに 1 つずつ取る**（`git_diff` の `untracked`）。`git diff` には
    出ず、数が多いことがあるので、まとめて `--no-index` で回さない
  - **root を焼き込まない**（`ChangesTab` の型の doc）。中身は Git パネルと同じ `status` で、
    操作も `activeRoot` に効くストアの関数なので、固定すると worktree の切り替えで一覧と操作が
    別のリポジトリを指す
  - **取り直しの契機は 2 つ**: `status` の中身（`statusKey`。10 秒ごとのポーリングは中身が同じでも
    オブジェクトを入れ替えるので、オブジェクトを見ない）と、ファイルの変更。**ファイルの変更は
    タブが自分で購読し、`status` に並んでいるファイルだけを拾う**（`watchedPaths`）: 増えたファイルは
    ポーリングが知らせ、ビルドの出力のような無視されたファイルで取り直さない。続けて来る変更は
    200ms 待ってまとめ、描かれていないタブでは取り直さない（diff タブと同じ）
    - **diff タブのように `App.vue` の照合に乗せない**（`git-diff.md` の「タブごとに `onFileChange` を
      購読する形にしないこと」の例外。あちらは diff タブと履歴タブの規則）。あちらが 1 か所に閉じているのは、タブごとに
      焼き込んだ root との照合と、自分の保存の印（`isRecentlySaved`）の消費があるため。このタブは
      `activeRoot` を見ていて印も読まないので、どちらも当たらない
  - **`statusKey` には `activeRoot` も入れる**。同じコミットの 2 つの worktree で同じファイルを
    直していると、切り替えても一覧が同じに見えて前の worktree の差分が残る
  - **未追跡のファイルだけが変わったときは、2 本の `git diff` を走らせない**（未追跡は
    `git diff` に出ない）。そのぶんだけ捨てて、選んでいれば取り直す（`dropUntracked`）。
    未追跡の取得の世代（`untrackedEpoch`）は捨てたときだけ進める: 取り直しの番号で見ると、
    取り直しが失敗したときに飛んでいた取得まで捨てられ「読み込み中」のまま残る
  - **コンフリクト中のパスは `git diff` に combined diff（`diff --cc`）で出る**。`parsePatch` は
    これを飛ばす（境目として扱わないと、続く行が直前のファイルの差分に混ざる）
  - **空白の無視は取れてから見方を変える**（`refetch` の引数で渡す。コミットタブと同じ）
  - **コミットは二重に走らせない**（`gitStore.committing`）。欄を通るまで残すので、待っている
    あいだにパネルとタブの両方から押せる
  - **10 秒ごとのポーリングで同じものを取り直さない**。未追跡のファイルの取得は選んだパスの
    文字列（`untrackedSelection`）で見て、取れなかったものは `'failed'` として覚える。開いた時点で
    `status` が無ければ、届いてからの `statusKey` の変化に 1 回目の取得を任せる
  - **ファイルの操作は `composables/useGitFileActions.ts`**（Git パネルと共有。git.md の #309 の
    「操作の実体は行のホバーボタンと同じ関数を呼ぶ」）。hunk 単位のステージは持たない
  - **コミットの欄は `gitStore.commitDraft`**（Git パネルと中身を共有。root ごとに持つので、別の
    リポジトリのメッセージが残らない）。欄を空にするのはコミットが通ったときだけ。タブから押した
    失敗は Git パネルの帯が見えないので、ステータスバーにも出す（`commitChanges` の `onFail`）
  - **ステージしたファイルは選んだまま反対の区画へ移る**（同じパスをもう一方の区画で探す）
  - 先頭行の点は HEAD のレーンに白抜きで描くが、**線は引かない**（HEAD が先頭のコミットとは限らない）
- **コミットのツールチップはパネルの横に出す（#374、`placeBeside`）**。上下に出すと展開したファイルの一覧や隣の行に重なる
- **グラフを必要以上に深くしない（#371）**。取得は `--all` ではなく `--branches --remotes --tags HEAD --date-order`（stash を除く理由と並び順の理由は `git_log` のコメントが正本）。取得範囲の外にいる親にはレーンを割り当てず、点線の短い線（`GraphRow.stubs`）で止める。割り当てると下で閉じる相手が来ないので、一覧の下端までレーンが開いたままになり、全行の幅を押し上げる
- ドラッグ中は `--graph-width` を DOM に直に書き、離したときだけ ref に入れる（全行がこの変数を読むので、ref にすると mousemove ごとに一覧全体が再描画される。diff の `--split` と同じ手）
